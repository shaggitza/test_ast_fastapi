# GH97 effect preset package and version matrix (v5 hermetic replay)

This artifact records exact release artifacts inspected for the GH97 preset audit, one filesystem analyzer replay, and six controlled package analyzer cases built from exact-artifact callable signatures and selectors. It does not claim that an entire declared compatibility range works. Each row names one package version and a SHA-256 pinned wheel or source archive; adjacent releases remain unaudited until separately recorded.

The matrix is deliberately split into three kinds of evidence:

1. **Package source inspection** records wheel/source archive bytes, package metadata where present, inspected file hashes, callable declarations, and selectors seen in that source.
2. **Preset contract inventory** records the preset ID, its own version and revision, source YAML hash, and contract count. Package source evidence does not validate the preset’s package version range.
3. **Analyzer observations** separate a synthetic filesystem fixture from six package analyzer fixtures run through the exact historical `MypyAnalyzer` and `audit_effect_contracts` source snapshot. Each generated receiver surface is derived from source signature and argument-selector evidence for its exact pinned artifact. Parameter names, positional/keyword binding kinds, required `TypedDict` keys, and all `Unpack[TypedDict]` keys are represented; annotations, runtime behavior, and installed implementation compatibility are not modeled. Contract-selected arguments must be present at the selected positional or keyword binding. The two S3 negative controls show that the analyzer still recognizes the exact symbol when `Body` is missing or passed positionally, while the matrix rejects both as incomplete selector bindings; they are excluded from positive totals. No fixture program, package client, service, database, URL, bucket, or application was executed.

The exact-release source inputs and shared analyzer snapshot are in [effect-preset-matrix-v4](../benchmarks/results/effect-preset-matrix-v4/): [package-symbols.json](../benchmarks/results/effect-preset-matrix-v4/package-symbols.json), [package-analyzer-cases.json](../benchmarks/results/effect-preset-matrix-v4/package-analyzer-cases.json), [source-signature-observations.json](../benchmarks/results/effect-preset-matrix-v4/source-signature-observations.json), and [analyzer-source-snapshots.json](../benchmarks/results/effect-preset-matrix-v4/analyzer-source-snapshots.json). The v5 [frozen runtime bundle](../benchmarks/results/effect-preset-matrix-v5/frozen-runtime.json) contains the exact first-party source closure and original `pyproject.toml`/`uv.lock` from commit `88ec7c33b45ec45435aaf7ffb72494c02f2328e4`, including the v4 artifacts. Those archived project files remain byte-for-byte unchanged; its original lock resolves `librt==0.7.8`, `pathspec==1.0.4`, Pydantic 2.12.5, `pydantic-core==2.41.5`, and `typing-extensions==4.15.0`, so it is not the provisioning lock for the later replay environment. Separately, `replay-envs/` contains one project and `uv.lock` per supported Python/mypy pair; their file set and hashes are authenticated by the v5 runtime manifest. These locks install the dependency versions explicitly recorded in that manifest, including the analyzer runtime distribution closure (`librt`, `mypy-extensions`, `pathspec`, Pydantic and its core, PyYAML, and typing-extensions), the current package import dependencies, and pytest/Ruff.  The seven analyzer runtime versions were observed in the four replay virtual environments used for this implementation; the v4 records do not contain original receipts for those additional distribution versions, so these lockfiles document reproducible replay environments and do not claim to recover missing historical receipts. A hash-checked isolated subprocess runs the historical provider against frozen v4 records; it does not import analyzer code from the current checkout. Six analyzer source paths and the separate test source hash remain required in the v4 evidence, and v5 verifies them against committed frozen source bytes. The child checks exact Python, mypy, and runtime distribution versions, uses isolated imports and a temporary working directory, bounds output, and does not execute the fixture. The v4 results and all v1–v3 records remain byte-for-byte historical. The pre-existing [effect-presets-v1 evidence](../benchmarks/results/effect-presets-v1/README.md) remains historical and is not relabeled as package compatibility or real-world recall evidence.

## Preset identities and version boundaries

The matrix freezes six independent preset contract sets by raw YAML hash, parsed ID/version/revision/count, and semantic hashes covering contract selectors: `redis-py-effects` 1.0.0/revision 1, `pymongo-effects` 1.0.0/revision 1, `stdlib-filesystem-effects` 2.0.0/revision 2, `python-http-client-effects` 2.0.0/revision 2, `typed-s3-effects` 2.0.0/revision 2, and `sqlalchemy-transaction-effects` 3.0.0/revision 3. The exact paths, hashes, and contract counts are in `versioned_contract_sets`. The verifier runs the strict historical `load_effect_contracts` implementation against the hash-pinned preset YAML and `package-symbols.json` copied from v4; it rejects caller manifest differences before replay. This keeps PR309’s later parser/normalization semantics from changing the meaning of v4 records. Their IDs and versions remain separate; no matrix version is used as a substitute for a preset version.

The audited release is compared with the current YAML range only as a cross-reference, not as compatibility proof. For example, `redis` 5.2.1 lies within the declared `>=5,<7` selector; only 5.2.1 source has been inspected. `pymongo` 4.10.1 lies within `>=4.9,<5`; this does not cover Motor. The filesystem artifact is Python 3.11.16, one interpreter release inside `>=3.10,<3.14`. `requests` 2.32.3, `httpx` 0.28.1, and `aiohttp` 3.11.11 are each one exact artifact. Typed S3 1.35.92 is one exact stub package inside the declared `>=1.34,<2` range. Range compatibility is therefore **not evaluated**.

The recent PR308 documentation commit `b612dc0` describes filesystem route/resource coverage. It does not add package-version observations and is not counted as matrix evidence. The v1 historical README describes controlled preset fixtures and infrastructure, not production package compatibility.

## Controlled analyzer observations

One synthetic pathlib fixture has independent static replay records for Python 3.10.21, 3.11.16, and 3.12.14 with mypy 1.19.1, plus Python 3.11.16 with mypy 2.4.0. These are the exact environments exercised here; they are not version-range or package-runtime compatibility claims. The frozen source is [pathlib_open_handles.py](../benchmarks/results/effect-preset-matrix-v4/fixtures/pathlib_open_handles.py). `load_controlled_results` replays those bytes through the hash-verified historical `MypyAnalyzer` and `audit_effect_contracts` snapshot in an isolated subprocess against the frozen `filesystem-v1` selector, without executing the fixture. Each environment-specific result binds the fixture and test source hashes, exact authoritative analyzer source path set, committed analyzer source snapshot hashes, the separately audited Python source artifact, preset ID/version/revision/raw/semantic/config hashes, resolver version, and package manifest/artifact identities. It stores one raw row per physical call. The loader validates the row schema, derives totals and negative-control counts from those rows, and requires exact agreement with a static replay in that same exact Python/mypy environment before accepting `completed`. v1, v2, and v3 results remain unchanged historical records.

Earlier CI failures exposed two distinct issues. The original cross-resolver mismatch was limited to the recorded `resolver_version`; v4 then added separate records for each exact supported Python/mypy pair. After the composed analyzer source changed in PR #312, v4 source-identity checks correctly rejected the live checkout, and the current filesystem summary also differed from the historical 9825f6d run. v5 therefore replays v4 only with its committed source closure and leaves every v4 observation unchanged. Current-checkout source is never accepted as a substitute for the historical bytes. A separate live control test runs the current analyzer and verifies that unrelated same-name methods do not match a contract; it does not impose historical aggregate counts on a newer analyzer. This does not establish all historical or current per-call statuses beyond the rows actually recorded.

Observed denominator: 11 calls; 4 matched, 7 unmatched, 0 ambiguous, 0 unresolved, derived from the 11 serialized observations and checked against replay. Positive coverage was `Path.read_text`, `Path.write_text`, and two `_io._TextIOBase.read` occurrences. Five unrelated same-name calls (`read_text`, `get`, `set`, `write`, `send`) remained unmatched; two open constructors remained unmatched. The Path.open-derived handle read had unavailable receiver origin (`receiver_origin_unsupported`); the built-in `open` handle read had exact origin. This is one source-level controlled observation, not an estimate of package-wide precision or recall.

Six controlled cases exercise exact-symbol preset binding for `requests.Session.get`, `aiohttp.ClientSession.get`, Redis `BasicKeyCommands.get`, PyMongo `Collection.insert_one`, SQLAlchemy `Session.add`, and typed S3 `S3Client.put_object`. Each analyzer surface is rendered from callable parameter names, binding kinds, and required parameters in the committed exact-artifact source-signature report, with source and selector hashes reconciled to the package manifest. The S3 surface expands `PutObjectRequestRequestTypeDef` to keyword parameters while preserving the pinned required `Bucket` and `Key` keys. For each positive case, the matrix verifies every parsed contract-selected argument binding before accepting it. Stored S3 controls replay the analyzer with `Body` omitted and misbound positionally; although the canonical symbol still matches, neither control counts as a positive because the selected value binding is absent. An unknown `BogusField` remains rejected against the pinned TypedDict. The fixtures use generated static types rather than importing upstream packages and do not establish installed-distribution behavior, every wrapper, version ranges, or runtime client behavior. The Motor public descriptor layer remains unsupported and has no positive analyzer observation; no PyMongo behavior is transferred to Motor. Generated boto3 operations remain distinct from the typed stub case below.

## Unsupported and missing evidence

- The exact request for `mypy-boto3-sqs==1.35.92` returned no matching distribution at the audited index. Version 1.35.91 is recorded as its own artifact; the unavailable version is not substituted or inferred.
- Motor 3.6.0 source inspection found descriptor delegation and generated framework-specific collection classes. Public-call resolution and analyzer binding are unresolved; no PyMongo result is transferred to Motor.
- SQLAlchemy source inspection and a synthetic `Session.add` symbol case cover only the exact 2.0.36 source archive and one preset operation; the declared `>=2,<3` range remains unevaluated.
- SQS 1.35.91 message operation declarations are source-audited, but the current message-bus preset has no exact package contract mapping for them, so no analyzer positive case is claimed.
- `boto3` operation methods are generated from Botocore service models. S3/SQS/SNS models were hash-inspected, but this matrix does not declare generated runtime client methods as analyzer-resolved callable symbols.
- No licensed, frozen real-world source diff was added. Real-world evaluation status is `not_evaluated`; no truth labels, package recall, runtime receipts, or production claims are fabricated.

## Reproduction and validation

Use the committed lock for the exact Python/mypy pair. For example, with uv 0.12.19 and the matching Python interpreter available:

```sh
uv python install 3.11.16
uv sync --project benchmarks/results/effect-preset-matrix-v5/replay-envs/python-3.11.16-mypy-1.19.1 --python 3.11.16 --managed-python --locked
PYTHONPATH=.:src uv run --project benchmarks/results/effect-preset-matrix-v5/replay-envs/python-3.11.16-mypy-1.19.1 --python 3.11.16 --managed-python --locked python -m pytest tests/benchmarks/test_effect_preset_matrix.py -q
```

Equivalent locked projects cover Python 3.10.21 / mypy 1.19.1, Python 3.12.14 / mypy 1.19.1, and Python 3.11.16 / mypy 2.4.0. The focused matrix suite is also run under the repository's normal installed project environments. Lock tests compare all seven recorded runtime distributions and the selected mypy version; a negative test rejects a wrong installed distribution version. Ordinary project CI installs the current project independently, and historical replay fails closed if that environment does not match one of the recorded runtime identities.
The supplied artifact directory must contain all twelve exact files named in the manifest. With any file missing, verification fails closed. The test suite does not download package files or contact external services. The v5 historical result verifier reads only the committed frozen source bundle and v4 synthetic sources; it does not run application code or load external clients. A separate live negative-control test observes the current analyzer but does not rewrite or validate historical v4 results. Only the four exact replay environments listed above have results; other interpreter/resolver combinations fail closed as unevaluated.
