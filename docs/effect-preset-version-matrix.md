# GH97 effect preset package and version matrix (v3 evaluation)

This artifact records exact release artifacts inspected for the GH97 preset audit, one filesystem analyzer replay, and six controlled package analyzer cases built from exact-artifact callable signatures and selectors. It does not claim that an entire declared compatibility range works. Each row names one package version and a SHA-256 pinned wheel or source archive; adjacent releases remain unaudited until separately recorded.

The matrix is deliberately split into three kinds of evidence:

1. **Package source inspection** records wheel/source archive bytes, package metadata where present, inspected file hashes, callable declarations, and selectors seen in that source.
2. **Preset contract inventory** records the preset ID, its own version and revision, source YAML hash, and contract count. Package source evidence does not validate the preset’s package version range.
3. **Analyzer observations** separate a synthetic filesystem fixture from six package analyzer fixtures run through `MypyAnalyzer` and `audit_effect_contracts`. Each generated receiver surface is derived from the source signature and argument-selector evidence for its exact pinned artifact. Parameter names, positional/keyword binding kinds, required `TypedDict` keys, and all `Unpack[TypedDict]` keys are represented; annotations, runtime behavior, and installed implementation compatibility are not modeled. Contract-selected arguments must be present at the selected positional or keyword binding. The two S3 negative controls show that the analyzer still recognizes the exact symbol when `Body` is missing or passed positionally, while the matrix rejects both as incomplete selector bindings; they are excluded from positive totals. No fixture program, package client, service, database, URL, bucket, or application was executed.

The current versioned records are in [effect-preset-matrix-v3](../benchmarks/results/effect-preset-matrix-v3/): the exact-release [package-symbols.json](../benchmarks/results/effect-preset-matrix-v3/package-symbols.json), [controlled-results.json](../benchmarks/results/effect-preset-matrix-v3/controlled-results.json), [package-analyzer-cases.json](../benchmarks/results/effect-preset-matrix-v3/package-analyzer-cases.json), [package-analyzer-results.json](../benchmarks/results/effect-preset-matrix-v3/package-analyzer-results.json), [source-signature-observations.json](../benchmarks/results/effect-preset-matrix-v3/source-signature-observations.json), and [analyzer-source-snapshots.json](../benchmarks/results/effect-preset-matrix-v3/analyzer-source-snapshots.json). The v1 and v2 result files remain unchanged as historical records; the v3 verifier accepts only v3 result identities. The pre-existing [effect-presets-v1 evidence](../benchmarks/results/effect-presets-v1/README.md) remains historical and is not relabeled as package compatibility or real-world recall evidence.

Ten declarations remain partial: four Motor descriptor assignments and six CPython C-level functions whose signatures are not Python function definitions. The report re-reads the exact supplied artifacts and rejects changed source signatures. The manifest stores the PyPI artifact URLs, release-source links, wheel metadata hashes where applicable, and every inspected source-file hash. Verification refuses missing artifacts, altered bytes, metadata mismatches, missing source files, or changed source hashes.

## Preset identities and version boundaries

The matrix freezes six independent preset contract sets by raw YAML hash, parsed ID/version/revision/count, and semantic hashes covering contract selectors: `redis-py-effects` 1.0.0/revision 1, `pymongo-effects` 1.0.0/revision 1, `stdlib-filesystem-effects` 2.0.0/revision 2, `python-http-client-effects` 2.0.0/revision 2, `typed-s3-effects` 2.0.0/revision 2, and `sqlalchemy-transaction-effects` 3.0.0/revision 3. The exact paths, hashes, and contract counts are in `versioned_contract_sets`. The verifier loads each file with the repository’s strict `load_effect_contracts` loader and rejects identity, count, semantic-selector or raw-byte mismatches. Their IDs and versions remain separate; no matrix version is used as a substitute for a preset version.

The audited release is compared with the current YAML range only as a cross-reference, not as compatibility proof. For example, `redis` 5.2.1 lies within the declared `>=5,<7` selector; only 5.2.1 source has been inspected. `pymongo` 4.10.1 lies within `>=4.9,<5`; this does not cover Motor. The filesystem artifact is Python 3.11.16, one interpreter release inside `>=3.10,<3.14`. `requests` 2.32.3, `httpx` 0.28.1, and `aiohttp` 3.11.11 are each one exact artifact. Typed S3 1.35.92 is one exact stub package inside the declared `>=1.34,<2` range. Range compatibility is therefore **not evaluated**.

The recent PR308 documentation commit `b612dc0` describes filesystem route/resource coverage. It does not add package-version observations and is not counted as matrix evidence. The v1 historical README describes controlled preset fixtures and infrastructure, not production package compatibility.

## Controlled analyzer observations

One synthetic pathlib fixture was analyzed with Python 3.11.16, mypy 2.4.0 and Ruff 0.16.10. Its frozen source is [pathlib_open_handles.py](../benchmarks/results/effect-preset-matrix-v3/fixtures/pathlib_open_handles.py). `load_controlled_results` statically replays those bytes through the repository’s `MypyAnalyzer` and `audit_effect_contracts` against the frozen `filesystem-v1` selector, without executing the fixture. The result binds the fixture and test source hashes, an exact authoritative analyzer source path set, committed analyzer source snapshot hashes, exact Python source artifact, preset ID/version/revision/raw/semantic/config hashes, resolver version, and package manifest/artifact identities. It stores one raw row per physical call. The loader validates the row schema, derives totals and negative-control counts from those rows, and requires exact agreement with a static analyzer replay before accepting `completed`. v1 and v2 controlled outputs are left unchanged as historical records.

Observed denominator: 11 calls; 4 matched, 7 unmatched, 0 ambiguous, 0 unresolved, derived from the 11 serialized observations and checked against replay. Positive coverage was `Path.read_text`, `Path.write_text`, and two `_io._TextIOBase.read` occurrences. Five unrelated same-name calls (`read_text`, `get`, `set`, `write`, `send`) remained unmatched; two open constructors remained unmatched. The Path.open-derived handle read had unavailable receiver origin (`receiver_origin_unsupported`); the built-in `open` handle read had exact origin. This is one source-level controlled observation, not an estimate of package-wide precision or recall.

Six controlled cases exercise exact-symbol preset binding for `requests.Session.get`, `aiohttp.ClientSession.get`, Redis `BasicKeyCommands.get`, PyMongo `Collection.insert_one`, SQLAlchemy `Session.add`, and typed S3 `S3Client.put_object`. Each analyzer surface is rendered from callable parameter names, binding kinds, and required parameters in the committed exact-artifact source-signature report, with source and selector hashes reconciled to the package manifest. The S3 surface expands `PutObjectRequestRequestTypeDef` to keyword parameters while preserving the pinned required `Bucket` and `Key` keys. For each positive case, the matrix verifies every parsed contract-selected argument binding before accepting it. Stored S3 controls replay the analyzer with `Body` omitted and misbound positionally; although the canonical symbol still matches, neither control counts as a positive because the selected value binding is absent. An unknown `BogusField` remains rejected against the pinned TypedDict. The fixtures use generated static types rather than importing upstream packages and do not establish installed-distribution behavior, every wrapper, version ranges, or runtime client behavior. The Motor public descriptor layer remains unsupported and has no positive analyzer observation; no PyMongo behavior is transferred to Motor. Generated boto3 operations remain distinct from the typed stub case below.

## Unsupported and missing evidence

- The exact request for `mypy-boto3-sqs==1.35.92` returned no matching distribution at the audited index. Version 1.35.91 is recorded as its own artifact; the unavailable version is not substituted or inferred.
- Motor 3.6.0 source inspection found descriptor delegation and generated framework-specific collection classes. Public-call resolution and analyzer binding are unresolved; no PyMongo result is transferred to Motor.
- SQLAlchemy source inspection and a synthetic `Session.add` symbol case cover only the exact 2.0.36 source archive and one preset operation; the declared `>=2,<3` range remains unevaluated.
- SQS 1.35.91 message operation declarations are source-audited, but the current message-bus preset has no exact package contract mapping for them, so no analyzer positive case is claimed.
- `boto3` operation methods are generated from Botocore service models. S3/SQS/SNS models were hash-inspected, but this matrix does not declare generated runtime client methods as analyzer-resolved callable symbols.
- No licensed, frozen real-world source diff was added. Real-world evaluation status is `not_evaluated`; no truth labels, package recall, runtime receipts, or production claims are fabricated.

## Reproduction and validation

Use a Python 3.11 environment with pytest, Ruff 0.16.10 and mypy 2.4.0. From the repository root:

```sh
python -m pytest tests/benchmarks/test_effect_preset_matrix.py -q
ruff check benchmarks/providers/effect_preset_matrix.py tests/benchmarks/test_effect_preset_matrix.py
ruff format --check benchmarks/providers/effect_preset_matrix.py tests/benchmarks/test_effect_preset_matrix.py
python -c 'from pathlib import Path; from benchmarks.providers.effect_preset_matrix import verify_artifacts, verify_preset_contracts, load_source_signature_observations; root=Path("/path/to/frozen-artifacts"); print(len(verify_artifacts(root))); print(len(verify_preset_contracts())); print(load_source_signature_observations(root)["counts"])'
```

The artifact directory must contain all twelve exact files named in the manifest. With any file missing, verification fails closed. The test suite does not download package files or contact external services. The v3 result verifier reads only frozen synthetic sources and repository analyzer/configuration files; it does not run application code or load external clients.
