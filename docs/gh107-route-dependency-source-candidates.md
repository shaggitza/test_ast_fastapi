# GH107 route dependency source candidates

This layer records supplied native dependency declarations at app, router, include, and route scopes as source uncertainties. It uses only the declaration-expression records attached to each endpoint's native provenance; it does not scan arbitrary registration or owner spans.

Each retained declaration site binds the physical route occurrence, exact typed handler owner, scope, canonical project source path/hash, and UTF-8 byte coordinates. Display spelling comes from that retained byte slice, capped at 256 characters, rather than the producer's rendered expression or callable spelling. The complete span and source hash retain the full source identity. Missing or changed source, empty/invalid UTF-8 spans, conflicting scope/side, and exhausted limits fail closed. Expression limits are 256 per endpoint and 8192 total, charged before deduplication; combined signature/declaration uncertainties also have an 8192-row limit. Each slice is limited to 1024 physical lines and 65536 bytes.

A mount boundary drops parent-side app/router/include declarations after the final mount; the child chain and route registration remain. All original assembly edges are still validated before trimming. Non-signature uncertainty rows require the fixed route-association reason, while signature reasons retain their existing validation. Schema 8 rejects older graphs whose mount scopes were collected under the previous policy.

The graph persists declaration sites and reconciles external uncertainty rows against that occurrence-specific projection. Signature candidates and positive source-binding ingress retain their existing containment requirement inside the exact typed handler. Graph/cache schema 8 includes scope and declaration sites. Cache validation regenerates the complete DI projection using authenticated current bytes and the retained typed snapshot, without parsing source or starting another mypy build. It compares complete DI edge/uncertainty rows and rejects extra or duplicated witnesses while preserving old unresolved-Depends and framework witnesses. Other uncertainty categories remain outside this DI-specific comparison. This performs a second graph walk; its performance is not measured here. Source uncertainty witness identity also includes the route occurrence, and both query paths filter these witnesses by occurrence so one registration's uncertainty does not propagate to an unrelated registration of the same handler.

All new records remain unverified. Native route association is supplied by the existing secure-AST provenance producer; this graph layer does not independently rederive its assembly chain. Selector implementation ownership, provider identity, dependency execution, and parameter transfer remain unproved. There are no new SourceDependencyBinding rows or provider edges. Queries may report conservative LOW potential evidence for unresolved declarations; that is not positive DI impact or a precision/recall result.

Validation uses the actual metadata validator, collector, query, and manifest methods with manually constructed endpoint/provenance/symbol records and inert byte arrays. No application, provider, archived source fixture, or mypy project build is executed by these controls. Hosted parser/build integration is still required for broader compatibility. GH107 remains open for authenticated selector ownership, positive provider transfer, legacy candidate parity, and performance acceptance.
