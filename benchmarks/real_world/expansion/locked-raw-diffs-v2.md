# Materializing locked raw diffs

`benchmarks/real_world/materialize_locked_diffs_v2.py` retrieves only the 50
diff URLs already bound to `fastapi/full-stack-fastapi-template` in
`pr-lock-2500-v2.json`. It captures the lock, manifest, and checksum profile
once, checks their SHA-256 values against pins computed from the committed base
tree, then applies the v2 semantic validators to those captured bytes before
making requests. It does not execute or parse downloaded content.

Run it with the repository's pinned interpreter:

```sh
/tmp/pr341-ci-host-locked-20261010/bin/python \
  benchmarks/real_world/materialize_locked_diffs_v2.py \
  --output /tmp/locked-raw-diffs-149-new-run
```

Each verified blob is stored once under `blobs/<sha256>`. `receipts.json`
contains one status for each locked row and records URL, expected and observed
hash/size, final URL, and blob path. Its `bytes` summary counts every byte
read, including bytes from failed validation rows, and reads stop at the remaining
aggregate budget. One wall deadline covers captured-input setup, network work,
cache verification/publication, and receipt publication; nested operations share
the same deadline and cannot extend it. Expiration during cache I/O leaves the
row missing with its fetched bytes still charged. Expiration during final receipt
publication may prevent a receipt from being written. Collection requires the
POSIX main thread and refuses to start while the caller has an active
`ITIMER_REAL`/`SIGALRM` timer, preserving that caller handler and timer unchanged.
If publication expires before its private temporary file can be removed, the
collector leaves that incomplete, mode-0600 `.raw-diff-*` file in place. It does
not report a successful publication or treat the temporary as a blob or receipt;
these deferred cleanup files are not automatically swept by a later run.
Failures include a structured
`failure_class`; HTTP failures also include numeric `http_status` without
recording response headers. Bytes returned by a successful fetch are charged
before cache storage, so local write failures cannot restore aggregate budget.
Local storage failures are reported as unavailable (`missing`), not content mismatches.
An HTTP error response is closed without reading its body; `bytes` counts bytes
read by this collector, not bytes the server may have sent in an unconsumed error
body. At an exact aggregate-budget boundary, a complete response is accepted
only when the concrete stdlib `HTTPResponse` has exactly one strict decimal
`Content-Length` equal to the locked size, no `Transfer-Encoding`, and reports
the fixed-length body fully consumed (`length == 0` and `fp is None`). This
allows a complete fixed-length response to use the full 443,496-byte ceiling
without reading a byte beyond it. Chunked, unframed, ambiguous, and otherwise
unproven responses remain unsupported at that boundary and are recorded as
`aggregate_budget`; declared size differences and truncation fail closed as
`size_mismatch` or `aggregate_budget`.
Existing output files are never replaced. Output
directories are opened component by component without following symlinks, and
creation and publication remain relative to those verified directory handles.
The collector enforces 2 MB per diff, 443,496 aggregate bytes, 180 seconds,
HTTPS-only exact-PR redirects, and the protocol's credential-free host rules.
Failed requests and lock mismatches remain explicit row statuses; the lock is
never rewritten to accept changed remote bytes.

A prior local acquisition from the original raw-source-only APP workflow retained
49 matching diff blobs (441,794 bytes) and one missing request for locked PR 2168.
That receipt predates this collector hardening; it must not be represented as a
cache generated by the current runner. The hardened collector uses offline controls
and is not rerun against remote URLs. Do not reuse an existing output directory or
substitute a different PR or diff for an unavailable locked row. This cache is
raw source collection only; it contains no reviews, adjudications, or truth labels.
