# Generated typed DAG accuracy gate (v1)

This harness measures endpoint candidate precision and recall on bounded, deterministic FastAPI source trees generated by `benchmarks/real_world/typed_dag_accuracy.py`. Its endpoint oracle is derived from the fixture generator's declared call-edge table, independently of analyzer output. It covers cross-file calls, alias imports, a reconvergent helper graph shared by two routes, live counterparts for literal-false, post-return, invoked-closure, invoked-lambda, and awaited-coroutine patterns, plus dead/unrelated controls. Every dead control wrapper is called from a route; the changed expression is checked to remain unreachable or deferred. Source-level callgraph guards reject disconnected controls and altered generator edges. The analyzer is invoked through the installed CLI in `--secure-ast --no-cache` mode; fixtures are synthetic and are never imported or executed.

Run it from the repository root:

```sh
uv run python benchmarks/real_world/typed_dag_accuracy.py \
  --output benchmarks/results/typed-dag-accuracy-v1/current-main.json
```

The command exits nonzero unless every supported case has 100% precision and recall and every dead/unrelated control has zero HIGH/MEDIUM candidates. LOW candidates are recorded separately as report-only. Each case stores paired baseline and target source, its diff and config, SHA-256 hashes, expected endpoints, actual endpoint/confidence rows, TP/FP/FN metrics, diagnostics, and the raw successful CLI report. The validator binds case metadata and expected endpoints to the declared oracle, regenerates exact fixture inputs, derives candidate rows from the hashed CLI report, requires established discovery of exactly two endpoints without analyzer errors or inventory limitations, and checks complete case coverage plus aggregate and tier metrics. It rejects non-finite values, duplicate/missing cases or candidates, tampered inputs, skipped supported cases, and false pass statuses.

Addition, deletion, and rename fixtures include explicit paired source snapshots and diffs, but are currently marked `unsupported`: the shipped mypy `ChangeMapper` does not map these changes against paired baseline/target symbol graphs. They do not count toward a pass. Re-run this gate after dependency integration; an unsupported or failed case never becomes a guessed pass.
