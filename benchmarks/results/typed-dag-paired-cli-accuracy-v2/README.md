# Paired generated typed DAG CLI accuracy gate (v2)

This version runs every declared case through the installed public CLI with both `--app` and `--baseline-app`, in `--secure-ast --no-cache` mode. The independent call-edge oracle is derived from the deterministic generator and never uses analyzer output. Baseline and target source maps, unified diffs, configuration, raw CLI JSON, endpoint candidates, confidence rows, diagnostics, and timing are recorded per case. Synthetic fixture source is never imported or executed.

Run against a clean integration worktree that contains the actual analyzer and CLI revision under evaluation:

```sh
uv run python -m benchmarks.real_world.typed_dag_paired_cli_accuracy \
  --analyzer-project-root /path/to/clean/analyzer-worktree \
  --output benchmarks/results/typed-dag-paired-cli-accuracy-v2/current.json
```

The runner revision and harness hash are recorded separately from the analyzer git revision, installed module paths, package versions, and SHA-256 hashes of the committed analyzer source files and lock/config files. The runner verifies the recorded runner revision contains the exact harness and fixture-generator bytes. It snapshots every analyzer source before and after each CLI call, and checks the final tree against the initial pin; any change makes the run invalid, sets gate status to failed, and preserves the captured per-case evidence with the initial/final identity details.

Each CLI run has an explicit timeout, records elapsed milliseconds, and streams stdout/stderr with a combined 4 MiB cap. The deadline remains active until both pipes close, even if the direct CLI exits while a descendant still holds a pipe open. On timeout or overflow, the runner kills the process group, drains for at most 250 ms, closes any remaining pipes, and bounds the final process wait. Such a case is recorded as failed with bounded output. It never materializes unbounded CLI output in memory.

The JSON hashes, source revisions, and command records are replay consistency checks; they are not an external cryptographic attestation that a process ran. The in-process evaluator requires ephemeral receipts created only as it collects subprocess results. A persisted `cli_generated` document alone cannot be revalidated into a passing gate, and the test suite includes a self-consistent forged-pass probe. This keeps the boundary explicit: the trusted event is the harness process invoking the pinned CLI and validating the result in memory, while the saved artifact is an audit record of that event.

The 15 established replacement and reachable-control cases are retained. Addition, deletion, and rename are separate capability probes with real baseline and target graphs: the new or removed function is called by `/one`, and both sides of the rename remain reachable. A probe is counted supported only after a real paired CLI run establishes the two-route inventory without errors or inventory limitations. A command failure is recorded as a failed case; an explicit analyzer limitation is recorded as unsupported. Neither can be guessed into a pass.
